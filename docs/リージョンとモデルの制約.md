# リージョンとモデルの制約

本ドキュメントは、本プロジェクトを**国内リージョン（東京 `ap-northeast-1` / 大阪 `ap-northeast-3`）に限定して運用する**という方針と、そこから生じる利用可能モデルの制約、および機能の取捨選択の判断をまとめたものです。

## 前提: リージョンは国内に限定する

データの所在を国内に限る方針のため、本プロジェクトは `ap-northeast-1` または `ap-northeast-3` でのみ運用します。

この方針は、閉域構成の実装によっても強制されています。

- **アプリのリージョンと `modelRegion` は一致していなければならない**（`packages/cdk/lib/closed-network-stack.ts`）。不一致の場合はスタックの合成時にエラーになります

  ```
  The app region and modelRegion must match in closed network mode (got X vs Y).
  ```

- Bedrock へは VPC エンドポイント（`com.amazonaws.<リージョン>.bedrock-runtime`）経由で到達します。VPC エンドポイントはリージョン内のサービスにしか繋がらないため、**別リージョンのモデルを呼ぶ経路が構造的に存在しません**

したがって「東京にデプロイしつつ、モデルだけバージニア北部を使う」といった構成は取れません。**使えるモデルは、デプロイ先リージョンで提供されているものだけ**です。

## 帰結: 画像生成は利用できない（2026-09 時点）

国内 2 リージョンにおける画像生成モデル（出力モダリティに `IMAGE` を含む基盤モデル）の状況は以下のとおりです。

| リージョン | 画像生成モデル | 状態 |
|---|---|---|
| `ap-northeast-1`（東京） | `amazon.nova-canvas-v1:0` の **1 つのみ** | **LEGACY**（2026-03-30 から）、**EOL 2026-09-30** |
| `ap-northeast-3`（大阪） | **0 件** | — |

画像生成用の推論プロファイルも両リージョンに存在しません（テキスト・埋め込み系のみ）。

さらに `amazon.nova-canvas-v1:0` は Legacy 期間中のため、**過去に利用実績のないアカウントからは呼び出せません**。実際に呼ぶと以下のエラーになります。

```
ResourceNotFoundException: Access denied. This Model is marked by provider as Legacy
and you have not been actively using the model in the last 30 days.
Please upgrade to an active model on Amazon Bedrock   (HTTP 404)
```

AWS のモデルライフサイクルの定義では、Legacy 期間中は「既存利用者は継続利用できるが、**新規の利用者はアクセスできない場合がある**」とされています。新規に構築した環境はこれに該当します。

### 判断: 画像生成の機能を非表示にする

以上より、国内リージョン限定の方針を維持する限り、画像生成を動作させる手段がありません。500 エラーを返し続けるより機能自体を隠す方が利用者にとって明確なため、パラメーターで非表示にしています。

```typescript
// packages/cdk/env-parameters/<環境>.ts
hiddenUseCases: {
  image: true,
},

// 使えないモデルを設定に残さない
imageGenerationModelIds: [],
```

`hiddenUseCases` はフロントエンドのビルド時に環境変数として埋め込まれるため、**変更にはフロントエンドの再ビルドを伴う `cdk deploy` が必要**です。

### 採らなかった選択肢

| 選択肢 | 不採用の理由 |
|---|---|
| 別リージョン（us-east-1 等）のモデルを使う | 国内限定の方針に反する。加えて閉域構成が `region === modelRegion` を強制しており、Bedrock の VPC エンドポイントも別リージョンには到達できない。組織の SCP でも他リージョンの Bedrock 呼び出しが明示的に拒否されている |
| Legacy モデルへのアクセスを申請する | Legacy 期間中の新規利用者は原則アクセス不可。かつ EOL が目前（2026-09-30）で、通っても短期間しか使えない |
| 画像生成のコードを削除する | upstream との差分が増え、追従コストが上がる。パラメーターで隠せば済む |

### 復活の条件

国内リージョンに ACTIVE な画像生成モデルが提供されれば、パラメーターの変更だけで復活できます。

```bash
# 国内 2 リージョンの画像生成モデルを確認する
for r in ap-northeast-1 ap-northeast-3; do
  echo "--- $r"
  AWS_REGION=$r aws bedrock list-foundation-models --by-output-modality IMAGE \
    --query 'modelSummaries[].[modelId,modelLifecycle.status]' --output text
done
```

`ACTIVE` のモデルが出てきたら、`imageGenerationModelIds` にそれを指定し、`hiddenUseCases.image` を外して再デプロイします。

## モデル選定時の確認手順

パラメーターの `modelIds` / `imageGenerationModelIds` を決める際は、**デプロイ先リージョンで実際に使えるか**を必ず確認してください。リージョンによって提供モデルが大きく異なります。

```bash
export AWS_REGION=<デプロイ先リージョン>

# 基盤モデル（ACTIVE のみ）
aws bedrock list-foundation-models \
  --query 'modelSummaries[?modelLifecycle.status==`ACTIVE`].[modelId]' --output text

# 推論プロファイル（jp. / apac. などのクロスリージョン推論を使う場合）
aws bedrock list-inference-profiles \
  --query 'inferenceProfileSummaries[?status==`ACTIVE`].[inferenceProfileId]' --output text
```

**注意**: 推論プロファイルの接頭辞はデータの処理先を意味します。`jp.` は国内リージョン内で処理されますが、`apac.` はアジアパシフィック各リージョン、`global.` は全世界のリージョンにルーティングされる可能性があります。**国内限定の方針を守るなら `jp.` 接頭辞のプロファイル、またはリージョン内の基盤モデルを直接指定してください。**

参考として、2026-09 時点の `ap-northeast-1` における `jp.` プロファイルは以下のとおりです。

```
jp.anthropic.claude-sonnet-4-5-20250929-v1:0
jp.anthropic.claude-haiku-4-5-20251001-v1:0
jp.anthropic.claude-sonnet-4-6
jp.anthropic.claude-opus-4-7
jp.anthropic.claude-opus-4-8
jp.amazon.nova-2-lite-v1:0
```

## モデルが使えないときの切り分け

Bedrock 由来の失敗はフロントエンドでは 500 エラーとしか見えないため、**Lambda のログを見るのが最短**です。

```bash
# 画像生成の場合
LG=/aws/lambda/$(aws lambda list-functions \
  --query 'Functions[?contains(FunctionName,`GenerateImage`)].FunctionName' --output text)
aws logs filter-log-events --log-group-name "$LG" \
  --start-time $(python3 -c 'import time;print(int((time.time()-3600)*1000))') \
  --query 'events[].message' --output text | tail -30
```

よくあるエラーと原因は以下のとおりです。

| エラー | 原因 |
|---|---|
| `This Model is marked by provider as Legacy` | Legacy モデルに新規アカウントからアクセスしている。ACTIVE なモデルへ変更する |
| `AccessDeniedException` / `You don't have access to the model` | Bedrock のモデルアクセスが有効化されていない。コンソールでモデルアクセスを有効にする |
| `ValidationException: The provided model identifier is invalid` | そのリージョンに存在しないモデル ID を指定している |
| タイムアウト・接続エラー | Bedrock の VPC エンドポイント（`bedrock-runtime`）または SG の問題。`closed-vpc.ts` の `VPC_ENDPOINTS` を確認 |
